# Trade Core17 盘后日报

本仓库负责每日行情准备、生产策略运行和中文日报发布，仅用于策略观察与人工决策支持，不连接券商、不下单，也不代表真实账户的持仓或成交。

## 查看日报

盘后日报以 Markdown 文件保存在 [日报目录](reports/)，文件名为交易日期，例如 `2026-09-22.md`。每份日报包含实际行情截止日、生产源码版本、运行记录、市场状态、市场风险、Core17 全部标的及相对前一交易日的变化。

完整保留生产字段和原始信号枚举，并使用中文标题、字段说明及状态解释。未输出的字段标注“未提供”；前一交易日结果无法核验时标注“不可比较”，不能解释为“无变化”。降级或失败必须如实保留，不能因为文件已发布就视为正常扫描。

## 运行安排

每周一至周五北京时间 17:06 计划启动，17:36 再做一次兜底检查，时区固定为 `Asia/Shanghai`。这只是启动时间，不保证该分钟内完成日报。每次先核验交易日历和收盘时间；休市日或尚未收盘时，不生成新的盘后信号，也不以旧日期报告冒充当天结果。当日指数、股票或风险篮行情暂未覆盖交易日时，计算占位前最多再等待两次，每次 10 分钟后重建输入快照并核验；其他错误或重试后仍缺失则如实失败。单次运行最长 90 分钟。兜底运行会复用已保存的当日结果，不重复计算；当日仍处于运行中或失败时，工作流保持失败状态。

正式工作流为 `.github/workflows/trade-daily.yml`，只允许本仓库 `main` 分支进入读取状态、计算和发布步骤；其他分支的手动触发会跳过正式任务。手动运行时可以填写已完成收盘的目标交易日，留空使用北京时间当天。部署变更会针对最近一个已完成交易日进行验收；已有结果时直接复用，不重新计算。

每次使用运行时最新的生产主分支和锁定依赖，记录实际执行的源码版本。Core17 成员及顺序从当次生产配置读取，不在本仓库复制固定名单。行情准备和策略计算沿用生产实现，不另造模型，不修改策略参数或风险规则。

## 同日去重与结果保存

连续状态、结构化结果和运行审计保存在本仓库独立的 `runtime-state` 分支。该仓库公开，因此运行原件使用认证加密，并在每次写入后按提交、对象摘要及解密内容回读核验。状态加密使用独立状态密钥，源码读取使用读取凭据；更换源码读取令牌不会改变状态密钥。状态密钥缺失或原件无法解密时，预检保持失败，不自动跳过或重置。

2026-09-30 经用户授权重新初始化运行序列，旧状态与旧原件不再参与计算；重置说明保存在状态分支。首次扫描沿用当前生产配置的起始日期和初始资金重新回放，首份日报与前一交易日不可比较。此前公开日报仅保留作历史记录，不作为新序列的连续状态。以后如需重置，须明确授权并记录新的起点；不得把重置称为旧状态恢复。

同一目标交易日最多开始一次策略计算。数据准备通过后，使用状态分支上的原子提交占位决定能否进入生产计算；并发锁用于串行调度。已开始但中断的计算不能通过删除记录来强制重跑。状态分支或网络暂时不可用时会用同一份已完成结果有限重试，并在写入不确定时先回读；已经占位而未能完成的记录需要根据加密审计人工核实，不能擅自重放策略计算。

结构化结果和运行原件完成一致性保存与回读校验后，发布程序只从已保存结果生成公开日报。重复执行发布会核验并复用相同文件；已有同日期文件与结果不一致时停止，不静默覆盖。写入结果不确定时先回读，确认是否已经保存，再决定是否补发。

日报提交只修改目标日期的 Markdown 文件，并回读核对字节长度、内容摘要和文件对象标识。报告目录的更新不会重新触发策略计算。计算完成、原件保存成功和公开日报发布成功是不同状态，必须分别核验。

## 公开范围

公开文档只展示经允许的行情、市场与风险信号、行动、资格、目标仓位及可追溯的运行信息。所有文档使用中文；为避免误读，生产信号枚举、标准标识和必要命令保持原样。

账户资金与持仓明细、订单标识、策略源码、内部服务位置、运行诊断和原始数据不进入公开文档。发布时从结构化结果中明确选择可公开字段，并检查文档内容；不直接复制完整运行对象或自由格式的错误日志。

## 维护与验证

日常维护优先检查目标日期、数据覆盖、运行状态和日报文件。数据缺失、过期或校验失败时保持失败关闭；存在旧结果时必须保留原日期、原版本和原状态。

本地定向检查：

```bash
python -m unittest discover -s tests -v
python public_report.py
```

这些检查验证运行编排、发布边界及文档内容，不等于策略收益验收。完整的实时扫描仍以实际生产运行和结果核验为准。

`.github/workflows/checks.yml` 在 PR、相关主分支变更或手动触发时执行同一组本地检查及文件完整性检查，只读取代码，不使用运行密钥、不读取连续状态、不执行生产策略或发布日报。

`.github/workflows/saved-evidence.yml` 只允许在本仓库 `main` 手动核验已保存的交易日原件：固定状态分支提交，认证解密既有包，检查配置身份、风险锁和参考篮历史日期。它仅公开允许的元数据，不公开金额、账户、包正文或密钥；不取新行情、不重跑策略、不写状态或日报。诊断不授权重置风险身份或解除买入限制。
